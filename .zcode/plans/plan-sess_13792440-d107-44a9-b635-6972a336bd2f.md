## Phase 2: Real local PR closed loop

### Goal
Wire a `--base/--head` revision pair through the server, compute a `ChangeSet` from read-only Git, and make `ComplexityRouter` route off server-derived facts instead of trusting user-supplied risk booleans. Backward-compatible: old manual flags stay as a deprecated fallback.

---

### 1. New domain objects — `src/reposentry/domain/changes.py`

Frozens-free dataclasses mirroring the existing `models.py` style (`@dataclass`, `to_dict()`, `@dataclass(frozen=True)` for value types).

- `RepositoryRevision(repository_path: str, sha: str)` — `sha` validated as a non-empty string starting with a hex-ish ref (no shell-meta chars); carries `to_dict()`.
- `DiffHunk(old_start, old_len, new_start, new_len, body: str)` — frozen; one `@@ ... @@` block.
- `DiffEvidence(base: RepositoryRevision, head: RepositoryRevision, path: str, line_start, line_end: Optional[int], hunks: List[DiffHunk])` — one file's diff; `line_start`/`line_end` derived from the min/max new-side hunk lines.
- `ChangedFile(path: str, status: str, additions: int, deletions: int, hunks: List[DiffHunk])` — `status` is one of `added|modified|deleted|renamed` (parsed from `git diff --numstat` + `--name-status`).
- `ChangeSet(base: RepositoryRevision, head: RepositoryRevision, files: List[ChangedFile], additions: int, deletions: int, dependency_changed: bool, api_contract_changed: bool, sensitive_paths: List[str])` — the aggregate the router consumes. Exposes:
  - `changed_files` -> `[f.path for f in files]`
  - `@property changed_lines` -> `additions + deletions`
  - `to_dict()` including `route_inputs` (the three derived booleans/lists, so the report shows *why* routing happened).
  - `is_within_root(path)` helper used by the parser to reject paths escaping the repo root (mirrors `Evidence.is_well_formed` style).

Heuristic detectors (pure functions on file paths), so they're unit-testable without git:
- `dependency_changed` → path in a small set: `requirements*.txt`, `requirements.lock`, `pyproject.toml`, `poetry.lock`, `package.json`, `package-lock.json`, `yarn.lock`, `go.mod`, `go.sum`, `Cargo.toml`, `Cargo.lock`.
- `api_contract_changed` → path matches `**/api/**/*.py` or `**/schemas.py` or `**/openapi.yaml` or `**/routes.py`.
- `sensitive_paths` → any changed path matching `**/auth/**`, `**/security/**`, `**/crypto/**`, `**/secrets/**`, `.github/workflows/*`, `**/settings.py`, `**/Dockerfile`.

### 2. Read-only Git skill — `src/reposentry/skills/git.py`

`GitClient(repository_root: Path)` (sibling of `RepositoryToolkit`). Same conventions as `repository.py`:
- Constructor resolves + validates root is a dir.
- Refs validated with a strict regex `^[A-Za-z0-9._/\-]{1,200}$` and rejected if they start with `-` (no `--exec=...` injection; mirrors existing `git_diff` guard).
- All subprocess calls use `git -C <root> ...`, `check=False`, `capture_output=True`, `timeout=15`, wrap errors in a `GitError(RuntimeError)`.

Methods:
- `resolve_revision(ref) -> sha`: `git rev-parse --verify <ref>^{commit}`, returns 40-hex SHA or raises.
- `diff(base, head) -> ChangeSet`:
  1. resolve both refs to SHAs,
  2. `git diff --no-ext-diff --unified=3 --numstat --name-status <base> <head> --` (single call, parse combined output),
  3. parse `--numstat` lines (`add\tdel\tpath`, handling `-/->/dev/null` for binary/renames) and `--name-status` (status letter + path, plus `Rxxx\told\tnew` for renames),
  4. parse the unified-diff body (which `git_diff` in `repository.py` already produces) into `DiffHunk`s per file via `@@ -a,b +c,d @@` regex,
  5. run the three detectors, build and return `ChangeSet`.
- A `DiffParser` pure helper class so parsing is unit-testable from a fixture file with **zero** subprocess calls.

### 3. Revision service — `src/reposentry/services/revisions.py`

`RevisionService`:
- `parse(base_ref, head_ref, repository_root) -> ChangeSet`: validates both refs via `GitClient.resolve_revision`, builds `RepositoryRevision` objects, calls `GitClient.diff`. Honors `Settings.repository_root` containment (reuse the same check `AnalysisService._resolve_repository` does).
- `to_request(change_set) -> AnalysisRequest`: projection so the existing orchestrator/router keep working unchanged for the legacy path.

### 4. Extend `AnalysisRequest` (`domain/models.py`)

Add three optional fields, keep existing ones untouched (deprecation fallback):
```python
base_revision: Optional[str] = None
head_revision: Optional[str] = None
change_set: Optional[Dict[str, Any]] = None   # serialized ChangeSet for the report
```
`to_dict()` already returns `asdict`, so they appear automatically.

### 5. `ComplexityRouter` — route from `ChangeSet` when present

- Add `route_change_set(change_set: ChangeSet) -> RouteDecision` (pure, deterministic) and have `route(request)` detect the new fields: if `request.base_revision`/`head_revision` are set, re-derive the score from the change set and **ignore** `dependency_changed`/`api_contract_changed`/`sensitive_paths` on the request. Otherwise fall back to today's behavior exactly (keeps `test_router.py` green).
- Same scoring bands as today (0–3 SINGLE, 4–8 TEAM, 9+ SWARM, same agents) so behavior is continuous.

### 6. CLI — `cli.py`

- Add `--base` and `--head` (strings, default `None`).
- In `run()`: when both provided, build a `GitClient` against the resolved repo, call `RevisionService.parse`, and feed `base_revision`/`head_revision`/`change_set` into the `AnalysisRequest`. Manual flags still populate the legacy fields and are used only when `--base/--head` are absent (deprecation warning printed to stderr).
- When neither base nor head is given, behavior is identical to today.

### 7. HTTP API — `api/schemas.py` + `api/app.py`

- Add optional `base_revision`/`head_revision: Optional[str]` to `AnalysisCreate` and pass through in `to_domain()`.
- In `AnalysisService._run`, before fanning out: if both revisions are present, run `RevisionService.parse` and store the serialized `ChangeSet` back onto the request so the orchestrator and the final report surface it. On `GitError`, fail the job with a clear message (job.status = "failed", job.error set) — same failure shape as today.

### 8. Agent review scope — `orchestration/orchestrator.py`

`_specialist_task` already serializes `request.to_dict()`, which now includes `change_set` (file list + per-file hunks). No structural change needed — agents read the change set from the task payload. I'll add a one-line instruction field in the task payload telling the agent to confine its review to `change_set.changed_files` when present.

### Acceptance check

```
reposentry --repo /path/to/repo --base <base-sha> --head <head-sha>
```
Output JSON: `request.change_set.changed_files`, `request.change_set.additions/deletions`, and `report.route.score/reasons` all derived from git, **not** from CLI booleans. Verified end-to-end in a new CLI smoke test that builds a temp git repo and shells out to `reposentry.cli.main`.
